# Tab Archive V1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans, test-driven-development, verification-before-completion. Owner explicitly approved proceeding without further review on 2026-10-26.

**Goal:** Archive background Chrome tabs into existing Notion data source after 5 minutes idle. Auto-close only after verified save, never risk current backlog.

**Architecture:** No server/dependencies. Chrome MV3 service worker owns private configuration, serialized tracking, Notion API writes. Content script marks changed form fields. Popup is small Arabic control and Notion archive link. Existing Notion DB remains the record store.

**Tech Stack:** Chrome MV3, ESM JavaScript, Notion API 2025-09-03, Node built-in test runner, PowerShell ZIP.

**Spec:** `docs/superpowers/specs/2026-10-26-tab-archive-v1-design.md`

## Global Constraints
- V1 only; embeddings/AI/transcripts V2. No new worktrees; keep existing files.
- Inactive background tab 5 minutes, 1-minute alarm; exclude active/pinned/audible/incognito/dirty/authenticated/sensitive.
- Do not write tokens to repo/logs/Notion. No auth until user configures personal integration.
- Preserve pre-existing tabs until selected/re-navigated. Close only after confirmed Notion save and second pre-close safety check.
- Local test first, tiny disposable-tabs dogfood only; protect production browser.

## Review Focus
- Notion timeout after create -> query existing row on retry; avoid duplicates.
- Navigation/activation while in-flight -> never close updated tab.
- Unsaved text in frames -> skip.
- Browser restart -> avoid treating restored backlog as fresh tabs.
- Malicious URL/token-bearing parameters -> skip without exfiltration.
